# Deploying Habits

The app (React) goes on **Vercel**; the API, the reminder cron job and Postgres go on **Render**,
all described in `vercel.json` and `render.yaml`. The browser only ever talks to the Vercel
address: Vercel forwards `/api/*` to Render, so the login cookie is first-party.

```
browser ──> your-domain (Vercel) ── /api/* ──> habits-api (Render) ──> habits-db (Render Postgres)
                                                habits-reminders (Render cron, every 5 min) ──┘
```

Check each provider's current pricing before you start; `render.yaml` uses the smallest paid plans
because free ones sleep, expire or skip backups.

## What you need

- A **GitHub** repository for this code.
- Accounts on **Vercel**, **Render** and **Resend** (password reset emails). **Sentry** is optional.
- For email: a domain you control, to verify in Resend. For the app: optionally a custom domain.

## 1. Push to GitHub and protect `main`

Push the repository. In GitHub → Settings → Branches, add a rule for `main` that requires the
**CI / check** status to pass. GitHub Actions (`.github/workflows/ci.yml`) then runs typechecks,
tests against a real Postgres and both builds on every push and pull request.

## 2. Create the secrets you'll paste in

Keep these somewhere safe (a password manager); you'll need them again for any new environment.

- **VAPID keys** (push notifications): `npm run push:keys -w server` prints a pair. Generate them
  once and keep them: new keys cut off every device that had notifications on.
- **Resend:** add and verify your domain (Resend shows the DNS records to add), then create an API
  key. `EMAIL_FROM` is an address on that domain, e.g. `Habits <hello@yourdomain.com>`.
- **Sentry (optional):** create two projects, "Node.js" for the server and "React" for the app, and
  copy each DSN.

## 3. Render: API, cron job and database

1. Render → **New → Blueprint**, pick the repository. Render reads `render.yaml`.
2. It asks for the values marked `sync: false`:

   | Variable | Value |
   | --- | --- |
   | `APP_URL` | The app's address, e.g. `https://habits.yourdomain.com` (or the `*.vercel.app` one for now) |
   | `CORS_ORIGINS` | The same address (comma-separate if there's more than one) |
   | `RESEND_API_KEY`, `EMAIL_FROM` | From step 2 |
   | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | From step 2 |
   | `VAPID_SUBJECT` | `mailto:` plus an address you read |
   | `SENTRY_DSN` | The Node.js DSN, or leave empty |

   `JWT_SECRET` is generated by Render. The API refuses to start if a required value is missing,
   and says which one.
3. Apply. Render creates the database, runs migrations before the API goes live
   (`preDeployCommand`), and starts the cron job.
4. Copy the API's address from the `habits-api` page (under its name). `onrender.com` names are
   shared by every Render user, so it usually has a suffix, like `https://habits-api-i1wt.onrender.com`
   (this project's). **Never assume the plain name:** `habits-api.onrender.com` belongs to someone
   else. Put the address in `vercel.json` (the first rewrite's `destination`) and push. Check it's
   really yours first: `/health` returns `{"ok":true}` and an unknown path returns
   `{"error":{"code":"not_found",...}}`.

Both services redeploy automatically after CI passes on `main` (`autoDeployTrigger: checksPass`).

## 4. Vercel: the app

1. Vercel → **Add New → Project**, import the repository. Leave the root directory as the
   repository root; `vercel.json` sets the install and build commands and the output folder.
2. Optional: add the environment variable `VITE_SENTRY_DSN` with the React DSN.
3. Deploy. `vercel.json` also sets the security headers (including a Content Security Policy),
   caching and the `/api` forwarding.

Vercel redeploys on every push. With the branch rule from step 1, only commits that passed CI reach
`main`. Note that **preview deployments** of other branches also forward `/api` to the production
API, so they use real data; for a separate staging setup, create a second Render Blueprint and
point a branch's `vercel.json` at it.

## 5. Custom domain and HTTPS

Add the domain to the Vercel project and create the DNS records Vercel shows. HTTPS certificates
are issued and renewed automatically. Then update `APP_URL` and `CORS_ORIGINS` in Render's
`habits-shared` environment group (reset-password links use `APP_URL`). The API keeps its
`onrender.com` address; people never see it.

## 6. Check it works

- `https://your-app/api/health` returns `{"ok":true}` (this goes through the `/api` forwarding).
- Sign up. In the browser's developer tools, the `refresh_token` cookie belongs to your app's domain,
  with `HttpOnly`, `Secure` and path `/api/auth`. Reload: you stay logged in.
- Forgot password: the email arrives and its link opens your app.
- Install the app (the browser's install icon, or Add to Home Screen on iPhone). In Settings →
  Reminders, turn notifications on and **Send a test**.
- Give a habit a reminder a few minutes ahead. Within 5 minutes of that time the notification
  arrives, and the Render cron job's log shows `Reminders: 1 habits, 1 people, 1 devices`.

### Confirm `TRUST_PROXY`

The login rate limit (10 tries per 15 minutes) is per visitor IP. Requests pass Vercel and then
Render's load balancer, so `TRUST_PROXY=2`. To confirm:

1. From one network, try logging in with a wrong password 11 times: the 11th says "Too many attempts".
2. Straight away, from a *different* network (e.g. a phone on mobile data), log in normally: it works.
   If it's blocked too, the API sees one shared address for everyone: raise `TRUST_PROXY` by 1.
3. Repeat step 1 with a made-up header, `curl -H "X-Forwarded-For: 1.2.3.4" ...`: it must still be
   limited. If the header lets you through, the value is too high: lower it by 1.

## 7. Monitoring and backups

- **Errors:** with the Sentry DSNs set, crashes in the app, API errors (500s), failed reset emails and
  failed reminder runs arrive in Sentry, without personal data. Set up an alert rule there.
- **Uptime:** add a free HTTP monitor (e.g. UptimeRobot or Better Stack) on
  `https://your-app/api/health` every 5 minutes. It checks both Vercel and the API.
- **Cron job:** Render can email you when a cron run fails (the reminder run exits with an error when
  it fails).
- **Backups:** Render's paid Postgres plans back up daily; check the retention for your plan and
  mention it in the privacy page. For an extra copy, `pg_dump` with the database's external URL.

## 8. Before going public

- **Privacy page** (`client/src/pages/PrivacyPage.tsx`): fill in every `[bracketed]` part: who runs
  the app, a contact email, the date, log and backup retention, the regions you chose, and any rules
  that apply where you operate. It describes what this code does, but it is a draft, not legal
  advice; have it reviewed if you can.
- Run through `docs/TESTING.md`'s manual checklist on a real phone.
